# buildings-render (scene/buildings.ts, architecture.ts, model.ts, materials.ts, colors.ts, thumbnails.ts, labels.ts, workshop/*)

## Summary
Buildings are pure data plus code. Each building is a JSON file (resources/games/content/epochs/buildings/<id>.json) with a rectangular `size {w,h}` in tiles and `levels[]`. Every LevelDef carries `epoch`, economy fields and `model.parts: ModelPart[]` (types.ts:847-870). A ModelPart is one of 35 kinds (box, roof, floors, windows, door, tower, prism, crown, columns, arches, balconies, cylinder, sphere, torus, tree, pole, light, emitter, blades, helipad, neon, solar, …; types.ts:374-822). Its coordinates are in tiles from the building's NW corner (x east, y south, z up). Colours are palette keys, "walls" or #hex. `buildModel()` (model.ts:434-980) handles the simple kinds and passes the architectural ones to `addArchitecture()`/`addStyledFloors()` (architecture.ts:835-1274). It turns the parts into non-indexed BufferGeometry, one per material "bucket" (matte/metal/glass/glow/windows/foliage/flag; materials.ts:11-22). All geometry uses vertex colours, plus `aLit` (vec4 colour plus a light-up threshold) on windows and `aWave` on flags. Moving parts come out separately as AnimatedSpec (only 'spin' and 'blink'). Smoke points become EmitterSpec, and glow points become LightSpec. The scene shares about 9 materials (createMaterials, materials.ts:152-280). The patches inject snow on upward faces (uSnow), night windows (step(aLit.a, uLit)) and waving flags (uTime). Colours come from the era palette: `game.paletteOf(building)` (game.ts:460-479) takes the palette of the level's OWN era (`content.levelPalette`, registry.ts:139-142), so a building never repaints when the era changes. A blueprint and the player's own colours are then merged on top. `resolveColor` (colors.ts:47-69) turns keys into colours, and an unknown key comes out magenta. `lookOf()` (buildings.ts:165-184) makes a cacheKey = lookKey + roof + wall variant index + lit-window seed (0..3). `ModelCache` (buildings.ts:57-108) shares the built geometry by reference count. The `Buildings` class runs `sync()` every frame (renderer.ts:342). It diffs game.buildings against what is drawn using a signature string (buildings.ts:285) and skips role 'road' (roads are drawn by roads.ts). A complete building has no mesh of its own. Its bucket geometries are COPIED and translated into one merged mesh per bucket per 8x8-tile chunk (CHUNK=8, buildings.ts:27; rebuildChunk 547-619 via mergeTranslated, model.ts:1800-1855). The chunk is picked from the building's top-left tile. A building under construction is drawn on its own (`individual` group): the model's scale.y grows 0.06→1 with game-time progress (buildings.ts:494-518), inside a wooden scaffold sized w×d×height (buildScaffold, model.ts:1692-1736). An upgrade keeps showing the previous level inside the scaffold. Fake contact shadows are one InstancedMesh of radial-gradient blobs, rebuilt whenever anything changes (buildings.ts:621-663). There is no LOD, no per-look instancing and no rotation: BuildingState has only x, y, level, style (state.ts:59-71), and placement is translation only. Picking is AABB ray tests over all entries (renderer.ts:831-871). labels.ts is a pooled DOM overlay with inline styles: warning badges, construction progress bars, floating texts and the white "new era" flash. thumbnails.ts renders a PNG data URL per (def, level, size) synchronously on one shared offscreen WebGLRenderer; ui/build.tsx:19-25 calls it inside useMemo. The Workshop (Workshop.tsx) is a desktop JSON editor for every content file, with live validation (validateContent), save/delete through PUT/DELETE /api/games/epochs/content/{key}, and previews (previews.tsx: BuildingPreview with ModelViewer, MapPreview with a random seed and square era territories, EpochsPreview, NPC and sound previews). SkyscraperStudio.tsx with skyscraper.ts lets you design a tower in metres (blocks, crowns, spires, …; presets Nest One, ESB, Burj, …). `toModelParts()` (skyscraper.ts:853-1089) fits it into the footprint and a 1-12 tile height and writes the result into `level.model.parts`, keeping the design in `level.model.studio`. No current level actually uses `studio`. Measured by running buildModel over all the content: models run 130-13,154 triangles. Examples: house L14 6.5k triangles / 800 KB of vertex data; skyscraper L5 13k / 1.6 MB; block L6 12.4k. In the content as a whole the matte bucket dominates (172k triangles in total, against 68k in windows).

## Key data structures
// content (types.ts)
interface BuildingDef { id; name; icon; category: Category; description; size:{w:number;h:number} /*1..4 enforced*/; unique; hidden; role?:'road'|'center'|'district'|'bureau'; placement:{requiresRoad; biomes?; nearWater?; overWater?}; sounds:{place,upgrade,demolish,select,ambient}; levels: LevelDef[] }
interface LevelDef { level; name; epoch:string /*palette+era*/; tech?; cost:Amounts; upgrade?:Amounts; buildTime; effects:Effects; model:{ parts: ModelPart[]; studio?: StudioSource } }
type ModelPart = {kind:'box',x,y,z,w,d,h,color,material?} | {kind:'roof',shape:RoofShape,x,y,z,w,d,h,color,axis?,overhang?} | {kind:'floors',x,y,z,w,d,floors,floorHeight,color,window,band?,facade?,cornice?,plinth?} | {kind:'tower',x,y,z,w,d,plan,r?,floors,floorHeight,taper?,twist?,facade?,color,window,trim?,cap?} | windows|door|beams|ground|field|cylinder|sphere|torus(spin?)|flag|pole(blink)|emitter(type)|light(radius)|tree(scale,conifer,z?)|prism|crown(style,glow?)|columns(pediment?)|arches|balconies|pilasters|cornice|crenels|dormers|awning|stairs|fence|solar|chimney(smoke?)|helipad|neon|clock|blades(axis,speed)
// coords: tiles from NW corner, x east, y south, z up; color = palette key | 'walls' | '#hex'
interface Palette { wall; walls:string[]; roof; trim; window; lit; glass; metal; road; roadEdge; roadMark:string|null; roadStyle:'dirt'|'cobble'|'paved'|'asphalt'|'smart'|'glow'; plaza; crop; flag; accent; sky:[zenith,horizon]; [key:string]:unknown /*extra keys usable from parts*/ }
interface BuildingState { uid; type; x; y; level; buildStart; buildEnd /*game time*/; style:{blueprint:string|null; colors:Record<string,string>}|null; district } // NO rotation

type Bucket = 'matte'|'metal'|'glass'|'glow'|'windows'|'foliage'|'flag'
interface ModelGeometry { buckets: Partial<Record<Bucket, BufferGeometry /*non-indexed: position,normal,color[,aLit vec4][,aWave]*/>>; animated: AnimatedSpec[]; emitters:{position,type}[]; lights:{position,radius,color}[]; bounds:Box3; height; dispose() }
interface AnimatedSpec { kind:'spin'|'blink'; geometry; bucket; pivot:Vector3; orient:Euler; axis:'x'|'y'|'z'; speed }
interface Look { cacheKey:`${type}:${level}:${blueprint}:${colors}|${roof}|w${wallIndex}|s${seed}`; palette; roof; wallIndex; seed /*0..3*/ }
interface BuildingEntry { uid; building; def; signature; cacheKey; model; chunk /*floor(y/8)*ceil(W/8)+floor(x/8)*/; base; complete; shownLevel; completeLevel; upgrading; box:Box3; animated; animatedGroup; individual /*under construction*/ }
// workshop studio (skyscraper.ts)
interface StudioSource { name; parts: StudioPart[] /*block|crown|spire|antenna|helipad|garden|lantern|bridge, metres, stack index*/; height /*tiles*/ }

## Requirement impact
### R1 [trivial]
The building renderer itself is map-agnostic: chunksPerRow = ceil(map.width/8) (buildings.ts:213), and the chunk index needs non-negative tile x/y (339-341). If v3's world grid includes the mountain and sea bands outside the playable 100x40, keep playable tiles at non-negative coordinates or add an origin offset. The town hall is already placed at the map centre by game.ts:179-190 (start.at === 'center'), and renderer.ts:202-210 centres the camera on it. Suggested change: with a 100x40 strip, use a non-square chunk (e.g. 10x10 or 16x8) to balance draw calls (65 chunks x up to 7 buckets plus a shadow pass is about 700 draw calls at full build-out today). Workshop MapPreview (previews.tsx:265-351) draws a random-seed map and square era territories, so it must be rewritten as a fixed-map preview with the 30-wide start strip and left/right expansion strips. EpochsPreview prints `territory*2 × territory*2` (previews.tsx:572-576).

### R2 [trivial]
Not owned here (the terrain skirt is in terrain.ts:134, 225-232, 573-640). In this subsystem only the Workshop/thumbnail plates show a slab: the ModelViewer plate is a BoxGeometry with sides (viewer.ts:173-188), and the thumbnail ground plate is at thumbnails.ts:125-139. Optionally make them flat discs fading out. Blob shadows (buildings.ts:621-663) are fine on a continuous ground.

### R3 [moderate]
Map trees and rocks are drawn by features.ts through model.treeGeometries() (model.ts:1784-1797). Drop that use or keep it only for decor. Building models still contain 329 'tree' parts (parks, gardens). Keep these: they are not map clutter, and addTree (model.ts:1040-1099) is reusable for street planters (R4). Because there is no building rotation, models can assume a fixed orientation on the fixed map: mountain = north (y−), sea = south (y+). Quarries/mines should be modelled with their working face on face 'n', and fishery/port/beach buildings with their front on 's'. Re-author quarry.json/mine.json/coal_mine.json models (and their placement rule, sim side) to stand against the mountain row. New beach/pier/port models need parts that can stand over water (placement.overWater exists, types.ts:899-900); terrain.baseOf clamps the base to WATER_Y+0.03 (terrain.ts:378).

### R4 [hard]
Roads are BuildingDefs with role 'road' (road.json: 9 levels, 0 parts). Buildings.sync skips them (buildings.ts:254), and roads.ts draws them procedurally from palette.road/roadEdge/roadMark/roadStyle (types.ts:189-190, 208-211; roads.ts:315-373), so today the look really is only a colour and style switch. For multi-lane avenues with sidewalks, markings, lamps and planters: (a) extend Palette/road content with new keys (sidewalk, curb, laneMark, median, planter, lampStyle, lanes). Palette already allows extra keys ([key:string]:unknown, types.ts:218), and resolveColor already resolves any key (colors.ts:66). (b) Rewrite roads.ts to build connectivity-aware geometry (straight/corner/T/cross; for 2-3 lane avenues probably a road type wider than 1 tile, or a 'lanes' attribute per road level). (c) Reuse this subsystem's primitives for street furniture: box/poly/append, addTree for planter trees, pole and light parts, the windows bucket with nightGlow for lit signs, and the materials/patches unchanged. Optionally add a 'connectable model' concept, i.e. model parts per neighbour mask, but procedural generation in roads.ts is simpler.

### R5 [hard]
Eras to 2100: delete e2300/e2500/e3000 from epochs.json and every level using them. The validators (registry.ts validateContent, ContentValidator.php:410) reject unknown epochs. Buildings that exist only after 2100 must go: ai_foundry, antimatter_collider, electrolyzer, fusion_reactor, nanofab, spaceport. Levels to trim: block L6-8, house L12-14, manor L7-9, market L8-9, school L9-10, skyscraper L3-5, town_center L9-11, farm L7-9, vertical_farm L2-3, composites_plant L2, data_center L2-3, architect_bureau L4, clinic L6, park L6, storehouse L7, theater L7, fishery L5, solar_farm L2, road L8-9. Metro/train/airport need large footprints. Raise the size cap in registry.ts:567-572 and ContentValidator.php:377 (now 1..4, e.g. to 16x8). The sim (canPlace game.ts:807-850, occupant map) and the renderer (scaffold w×d, baseOf/flatten, chunk by top-left tile) already handle any w×h rectangle. Missing pieces: (1) Building rotation. BuildingState has no `rot` (state.ts:59-71), and mergeTranslated only translates (model.ts:1800-1855). Add rot 0..3, swap w/h in canPlace/footprints()/scaffold/blob shadow/label centre/picking box, and add a mergeTransformed that rotates positions and normals by 90° steps (cacheKey can stay rotation-free). (2) Linear networks. Rail tracks and metro lines (and maybe taxiways) are road-like tile networks, not buildings, so they need a new network layer in roads.ts/sim. Stations are buildings that must connect to it. (3) Animation. AnimatedSpec supports only 'spin' and 'blink' (model.ts:38-50, 1745-1781); trains and planes need path/shuttle movement here or in people.ts traffic. (4) Big flat footprints look wrong with today's construction (scale.y squash + scaffold, buildings.ts:411-433, 510-512) and the radial blob shadow (621-663). Add per-def options such as construction:'scaffold'|'ground', shadowBlob:false. (5) Thumbnails of wide buildings need a custom framing or an icon (thumbnails.ts:141-178). The fixed map makes it possible to reserve the airport lot (e.g. a runway along x near the beach).

### R6 [trivial]
The render side is already mostly right: each level is drawn with its own era palette (registry.ts:139-142, game.ts:460-479), so an era change does not repaint existing buildings, and construction progress uses game time (buildings.ts:500-506, game.ts:265-267). Era-switch visuals that 'change everything': the white flash plus 260 confetti on the 'epoch' event (renderer.ts:672-686, labels.ts:238-240, 270-274), and the instant sky palette swap (sky.ts:65 via game.palette, game.ts:205-207). Remove these or blend them over time; colors.ts mixColor can interpolate palettes by year. The Workshop EpochsPreview shows yearsPerDay (previews.tsx:572), which goes away with a constant calendar rate.

### R7 [trivial]
No currency is rendered in this subsystem. Only touch points: floating texts from events (renderer.ts:615-623, 657-666), status badges (renderer.ts:518-539: 🚧 ⚡ 📦 👷), and the Workshop BuildingPreview cost line (previews.tsx:214-224), which lists every resource. Change these to show the single main currency (symbol per era) plus resources. Era-specific currency props (coin mint, bank, ATM/card terminal) can be ordinary model parts.

### R8 [moderate]
Rendering has no economy logic. New economic states (unemployment, no customers, traffic, land value, upkeep debt) need new badge reasons in renderer.updateLabels (480-556), and possibly heat-map overlays (overlays.ts TileMesh). BuildingPreview facts (previews.tsx:204-241) must follow the new Effects schema.

### R9 [hard]
labels.ts uses inline styles (fixed 12px/14px fonts, 38x6px bars; 94-133, 216-224). Move them to CSS classes (scene-badge/scene-progress/scene-float already exist) so the new design system and mobile scale can restyle them, and limit the badge count when zoomed out. Thumbnails render synchronously inside React render (ui/build.tsx:19-25, thumbnails.ts:67-96). On mobile, the first build-menu open renders ~40 WebGL frames plus toDataURL and janks. Pre-bake thumbnails (a build-time script or the Workshop exporting PNG/atlas) or queue them through requestIdleCallback. Mobile performance (critical for a 100x40 city): models are non-indexed, measured at 130-13,154 triangles and up to 1.6 MB of vertex data each. Complete buildings are copied into chunk meshes (mergeTranslated), so memory grows linearly with buildings, and both the cache and the merged arrays stay in the JS heap. Fixes: (a) per-look InstancedMesh, or at least free merged arrays after upload; (b) indexed geometry and Uint8 normalized colours; (c) reduce look variants. wallIndex (palette.walls) x seed (0..3) gives up to 16 geometries per level (buildings.ts:173-178); move these to per-instance attributes. (d) LOD: a box/impostor with a window shader beyond some distance. (e) sync() rebuilds a signature string for every building every frame (buildings.ts:251-299); drive it from the sim's changedBuildings revision instead. (f) setXray flips transparency on every material, which recompiles shaders (materials.ts:253-269). Quality presets exist in renderer.ts:237-264 (pixel ratio, shadow map size). The Workshop is desktop-only, which is acceptable for a dev tool.

## Risks
1) No building rotation anywhere: state, placement, models and merge. Every model assumes south-facing doors/fronts ('s' faces). A rail station or airport aligned with tracks or a runway needs rotation, or the content must accept fixed orientation, which a fixed map makes viable. 2) Footprint cap 1..4 is enforced twice (registry.ts:567-572 and ContentValidator.php:377); both must change together. 3) A large footprint is assigned to the chunk of its top-left tile only (buildings.ts:339-341), which grows that chunk's bounding sphere and weakens frustum culling. Any change in a chunk re-merges all of it (rebuildChunk allocates fresh Float32Arrays and iterates all entries for every dirty chunk). 4) Memory on mobile: at roughly 800 buildings averaging 2-3k triangles, merged chunk data is on the order of 150-250 MB of CPU+GPU vertex data, plus cached per-look geometry. There is no LOD. The biggest triangle counts are in the 2000-2100 era levels that v3 keeps (skyscraper L1 9.1k, house L11 6.5k, block L4 11.4k). 5) Look-variant explosion: cacheKey includes the wall variant (up to 4 per palette) and the lit seed (4), so sharing is weak; per-instance attributes would need shader changes in materials.ts. 6) Bug: levelHeight() (buildings.ts:437-454) only counts parts with numeric `h` or kind 'floors'. 'tower' parts (floors*floorHeight, no h) count as 0, so the upgrade scaffold is too short for tower-based levels (skyscraper/block). 7) The construction animation scales the whole model in Y (buildings.ts:511), which squashes windows and roofs; it looks odd for big flat structures (runway, platforms). 8) The blob shadow is a radial gradient stretched over the footprint and becomes a big dark ellipse under wide buildings. 9) Two extra WebGL contexts (thumbnail renderer plus Workshop ModelViewer); mobile browsers cap the number of contexts. Thumbnails use preserveDrawingBuffer and synchronous toDataURL. 10) labels.ts appends a DOM node per badge or progress bar and moves it every frame; it can get heavy on mobile with many constructions. 11) Palette semantics: unknown palette keys render magenta (colors.ts:66-68), so new road/currency keys must be added to every era palette or given #hex fallbacks. 12) Era-specific sky (sky.ts:65) and the flash/confetti on era change contradict R6. 13) Content authoring cost: models are hand-written JSON (house.json 98 KB, block.json 104 KB). The SkyscraperStudio only covers towers (it ignores twist/rot and turns taper into stepped tiers), so new metro/rail/airport buildings need hand-made part lists or a new studio-like generator. 14) The Workshop hardcodes the epochs slug, routes and '/city2' links (Workshop.tsx:154, 222, 286, 359, 410; content-api.ts:24). Rename all of them when copying to the self-contained v3 folder. 15) Windows on Windows: the `render/iso.ts` 2D helpers are only used by Workshop sprites and overlays; check before deleting.

## Reusable
Keep as-is: the whole parts-to-geometry pipeline (model.ts buildModel plus architecture.ts). It is a rich, data-driven procedural architecture kit (35 part kinds, 9 facade styles, plan outlines, roofs, crowns, colonnades, neon, helipads) that produces good-looking era-specific buildings from compact JSON. Also keep: the bucket/material scheme with vertex colours (about 9 shared materials, few state changes) and its shader patches (snow, night windows with per-window light-up thresholds, waving flags); per-level era palettes with 'walls' variants and blueprint/player colour overrides (buildings keep their era look, which matches R6); ModelCache refcounting; chunked static merging (keep the idea, retune chunk size and add instancing/LOD); the construction scaffold plus showing the old level during an upgrade; emitters and lights collected from models (smoke, glows); the AABB picking and Labels DOM pool (restyle via CSS); thumbnails (make them async or pre-baked); the Workshop with live validation, the ModelViewer preview with palette/night/snow toggles, and the SkyscraperStudio, whose toModelParts fitting into any footprint works for tall towers in the 2000-2100 eras. colors.ts helpers (resolveColor, hash3, mixColor) are generic and reusable.
